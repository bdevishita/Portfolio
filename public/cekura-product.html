Cekura Design: Web App & Product Screens

How I designed the dashboard of an AI agent testing platform, and the reasoning behind each screen.

RoleFounding Product Designer
CompanyCekura (YC F24)
Timeline08.2024 – Present
CollaboratorsPM, frontend developers

Context

Cekura lets teams simulate conversations with their voice and chat agents, score results with LLM judges and custom metrics, and monitor production. Users are engineers and QA leads who read a lot of data. The job of every screen is to turn that data into a decision quickly.

My process: design in Figma, prototype in HTML/CSS/JS where interaction matters, then hand off to the frontend developer with clear states.

Key decisions

Run result & evaluation overview

Flatten the tabs, promote the rubric

The detail page split metrics into Boolean, Rating and Analysis tabs, which hid results behind clicks. I replaced them with one neutral metrics grid, made the rubric the primary visual focus, and added labeled key-value chips in the header.

Trust in LLM judges

Confidence as a visible state

Judge metrics now carry a confidence badge in three tiers, so a reviewer knows what to double-check first.

HighMediumLow
Connection types

Specific badges over a Voice/Text binary

A UX audit showed "Voice" or "Text" told users almost nothing. I replaced it with the real connection type.

TelephonySIPLiveKitPipecatWebSocket
Compare transcripts

Two sides, clearly labeled

Client vs. Cekura transcripts are labeled and separated with colored left borders, so differences read at a glance instead of needing a legend.

Edit metric

Versioning that feels like version control

Sequential v0 / v1 / v2 labels, inline diffs, a Compare Versions panel and restore/rename modals make it safe to iterate on a metric without fear of losing the old one.

Metrics table

Predefined vs. custom, grouped

Group headers with pill labels and count chips separate predefined and custom metrics, so a long table stays scannable.

Applying UX laws on the results page

When I redesigned the results page I used named principles as a checklist rather than decoration:

Hick's Law · fewer choices per view Von Restorff · one clear highlight Miller's Law · chunk the data Fitts's Law · reachable targets Progressive disclosure · detail on demand

How I work

Minimal, brand-faithful, no decoration for its own sake. I prefer a neutral grid with one point of emphasis to a screen where everything competes. Decisions are written down with the question they answer, so developers and the PM can challenge them.
